## Execution flow

1. The screen collects the source and feature options. Its frontend defines button handlers and dropdown values.
2. The frontend sends a local API request. The server checks the request and delegates to a feature handler or job service.
3. The implementation validates inputs and calls its processing, model, retrieval, or native editor adapter.
4. The result is saved locally and reported through a response or job status. The screen provides preview, review, and available export controls.
5. Native editor work and account operations require a result check in the receiving application.

This shared sequence is a navigation guide. The linked feature implementation contains the exact route, branches, state changes, and return values.

## Buttons and their purposes

| Control | Purpose |
| --- | --- |
| Read open After Effects project | Reads the current open After Effects project through the native connection. |
| Inspect template | Inspects the selected template and reports its editable slots. |
| Restore saved native work | Reopens the saved native curation state. |
| Load reviewed footage | Loads reviewed footage candidates to use in template slots. |
| Propose slots from story | Proposes footage placement based on the chosen story. |
| Download slot map JSON | Downloads the mapping of source footage to the template slots. |
| Save separate populated project | Creates a separate native project with the chosen slots populated. |
| Render native preview | Requests a preview from the connected After Effects host. |
| Create native intro comparisons | Builds comparison projects for reviewing different intro treatments. |
| Render selected comparison | Renders the selected comparison project through the connected host. |

Common and dynamic button families are also documented in the source voice catalogue. Dropdown options are defined in the actual HTML and JavaScript.
