Audio mechanisms now established by source
==========================================
1. The mixer uses the Web Audio API with gain nodes, buses, filters and custom
   AudioWorklet processors. This is ordinary audio processing infrastructure,
   distinct from the server-side sound selection model.

2. The sidechain worklet has two inputs: the audio being controlled and a key
   signal (dialogue when routed by the previously inspected Studio controls).
   It filters each key channel, measures a smoothed mean-square envelope, and
   uses the largest channel level. Threshold, ratio and optional soft knee
   determine desired reduction, bounded by a maximum reduction setting.

3. The optional key gate prevents a sufficiently quiet key from activating
   reduction. When enabled, a fixed 0.2-second gate hang bridges short gaps.
   It is disabled at the processor's default floor; do not claim every project
   automatically has breath/room-noise rejection enabled.

4. Gain changes are smoothed in dB with separate attack, hold and release.
   The reduction is then applied to program samples. Metering reports both key
   level and gain reduction. Default values and clamps are visible, but no
   listening or numerical DSP validation was run. Do not promise identical sound
   merely by copying these parameter values.

5. The limiter factory supports native DynamicsCompressor and custom-worklet
   paths. The worklet contains look-ahead ring buffers with a 6ms pre-delay
   setting and a shaped release. A helper creates a missing master limiter
   BYPASSED, so presence alone does not establish active limiting in the sample.
   No true-peak guarantee, actual ceiling or sample's active engine was measured.

6. Clip fade scheduling scales fade-in/out together if they exceed clip duration.
   It uses exponential approach via AudioParam.setTargetAtTime plus endpoint
   ramps, and accounts for playback starting partway into a fade. This helps
   preserve fade behavior when seeking instead of restarting every envelope.

7. The offline mix renderer rebuilds saved master/group/channel processing in
   a stereo OfflineAudioContext, respects mute/solo-derived audibility, resolves
   bus routes and awaits sources and processors. It explicitly fails when a
   required processor cannot load instead of silently exporting a passthrough.
   This resolves the earlier uncertainty about the full browser mix graph;
   the earlier export-bundle OfflineAudioContext was only a resampling step.

Independent Storylens implementation implications
=================================================
- Retain a continuous music bed where the scene supports it; layer ambience and
  brief action cues separately instead of forcing every sound into one budget.
- Rank available music using distinct mood, tempo, instrument and vocal metadata,
  then measure placement. Catalogue size and licensed assets remain separate
  requirements; this inspection did not copy Epidemic's audio library.
- Implement bounded dialogue-keyed gain envelopes with optional noise gating,
  short-gap bridging and separate music/effects settings using our own mixer.
- Preserve trims, fades, cue identities and processor settings across preview,
  rebuild and export. Surface missing-asset/processor errors before producing a
  misleading successful result. Use Storylens's shared error presentation.
- Evaluate browser Web Audio only if interactive preview benefits. Existing
  FFmpeg and native-editor exports need not be replaced to use these principles.
